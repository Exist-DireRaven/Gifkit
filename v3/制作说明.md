- `gpt_pairs72.png`：9 个 pair 块 × 8 帧 = 72 帧（按我给的 pair 分组）

## 1. 先说动作逻辑问题

你指出的"同一张动图里既有枪又有拳击不合情理"——**成立**。原素材是一条把
「远程武器连段」和「近战格斗连段」硬接在一起的序列：角色先抬炮、瞄准、开火、
收枪，然后紧接着打直拳、旋身。玩家视角里没有任何因果关系（刚把枪收起来就改用拳，
中间没有"枪打完了/被逼近了"的动机）。

**方案：拆成两条各自自洽的循环，任何一条里面都只有一种攻击方式。**

| 成片 | 内容 | 帧数 | 时长 |
|---|---|---|---|
| `mimo3_gun.gif` | **枪械连段**：起步 → 前冲 → 压低 → 抬枪 → 瞄准 → 开火 → 收枪 → 待机（抱兔） | 38 | 1.83 s |
| `mimo3_melee.gif` | **格斗连段**：待机 → 直拳 → 旋身攻击 → 收势回待机 | 14 | 1.47 s |

顺带把之前你吐槽的**跳跃段整段排除**了——这次只用 key02–key11 的素材，
不含起跳/腾空/落地。

## 2. GPT 素材的体检结果

| 检查 | 结果 | 处理 |
|---|---|---|
| 两图是否同一批帧 | 图2 每帧在图1 里的最佳匹配 IoU **中位数 0.706**（1.0 才是同一帧） | **只取图2**，不混用，避免风格/比例漂移 |
| 角色大小漂移 | 原始帧高 90–127 px，**跨度 41 %** | 用块边界"同一姿势的两次绘制"做 IoU 最大化的比例估计，累计缩放 **1.00 → 0.65** 归一 |
| 块边界重复关键帧 | 每块的第 1 帧与上一块的第 8 帧是同一姿势但画得不一样（如块1 末 104 px vs 块2 首 116 px） | **丢弃每块第 1 帧**，消除重复关键帧造成的跳变 |
| 中割分布不均 | 出拳块前 3 帧几乎静止、后 3 帧突变 | 改为**按累计运动量等分采样**，让姿势推进均匀 |
| 背景 | 是 251–254 的脏白，不是纯白 | 从图像边界做 flood fill 分离背景，输出干净白底/透明底 |
| 枪的连续性 | 收枪段（第 7 块）枪**整段消失**，兔子是"突然出现"的 | 无法修复（素材缺失），把该段中割压到最少、时长压短来弱化 |
| 块尾姿势偏差 | 如旋身块收尾与原始 key11 有偏差 | 保留，仅作收势处理 |

## 3. 成片处理流程

1. **提取**：连通域聚类定位 72 个角色（自动跳过网格线与文字标注），逐格裁出。
2. **比例归一**：块边界上用 IoU 最大化估计缩放比，把 9 个块统一到同一角色高度。
3. **对齐**：每帧统一到 320×320 画布，脚底压在地平线 y=296，身体质量中心水平居中。
4. **按运动量选帧**：每个转场按累计运动量等分挑 3–5 张中割，动作推进均匀。
5. **节奏**：运动帧落在 **1/24 s 网格**（40/50 ms 混合，实测 23.8–24.0 fps）；
   开火后 150 ms、出拳后 190 ms、旋身后 260 ms、待机 300 ms 定格。
6. **收势**：格斗段旋身结束后用 3 帧运动补偿过渡回待机，避免硬切。

## 4. 已知残留问题（诚实说明）

1. **枪在"收枪 → 抱兔"段消失**（第 7 块）：这是 GPT 素材本身没画，只能靠短促过渡弱化。
   要彻底解决需要补画"枪斜挎到身侧 + 手去抱兔子"的中割。
2. **循环切点**：两条 GIF 结尾都停在待机、开头是起步，循环时有一次姿势切换。
   这是素材首尾姿势决定的，属于"重置"式循环。
3. **分辨率**：GPT 分镜每格角色只有约 100–130 px 高，成片放大到 238 px，
   细节比原始 352 px 素材略软。
