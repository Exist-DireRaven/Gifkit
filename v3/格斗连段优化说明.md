# 格斗连段 v4 优化说明

在 `mimo3_melee.gif`（v3）基础上继续优化，产物为 `mimo4_melee.gif`。

---

## 1. 优化前后对比

| 指标 | v3 | v4 | 说明 |
|---|---|---|---|
| 地平线抖动 | **11 px** | **0 px** | v3 的收势帧（光流合成）没重新对齐，整段往下掉了 7–11 px |
| 水平重心偏移 | 4.7 px | **0.9 px** | 同上，合成帧重新对齐后消失 |

## 2. 逐项修复

### 2.1 收势帧的对齐漂移（最明显的问题）

v3 的收势帧是用光流变形合成的，但变形后**没有重新对齐**，导致地面线从 296 掉到 303、307，
画面上就是"人物突然往下沉一下"。

v4 里每一帧（包括所有合成帧）都重新走一遍对齐：包围盒底边压到 y=252，
身体质量中心对到画布中线。抖动归零。

### 2.2 出拳太跳

v3 用"按累计运动量等分"自动挑帧，结果挑到 b8.2、b8.3 两帧几乎和待机一样，
然后一步跳到出拳。看原始素材：b8.0–b8.3 基本是待机，动作全在 b8.4–b8.7。

v4 改成手工指定 **b8.3 → b8.4 → b8.5 → b8.6 → b8.7**，
出拳有了"轻微预备 → 抬臂 → 前送 → 到位"的递进。

### 2.3 出拳→旋身的接缝

块 8 的末帧（出拳）和块 9 的首帧是 GPT 分开画的，直接接上重合度只有 0.726。
v4 在两帧之间插入 2 张运动补偿帧，并把接缝提到 **0.838 / 0.888**。

### 2.4 旋身用满素材

v3 只用 4 帧旋身，v4 用满 GPT 画的 7 帧（b9.1–b9.7），
并对内部最大的一步（b9.5→b9.6，重合度 0.713）自动补了 1 张运动补偿帧，
把它抬到 0.872。

### 2.5 收势改成"双源切换"

v3 的收势全部从前一帧往前推，最后一帧（变形到 75%）跳到待机，重合度只有 0.699。
v4 改成：前段用旋身帧往前推、后段用**待机帧往回推**，
于是最后一步只差 20%，跳到待机时重合度 **0.903**。

### 2.6 清晰度

- 原来对每帧做了两次缩放（先按块比例、再按目标高度），两次 LANCZOS 叠加会发虚。
  v4 合并成**一次重采样**。
- 重采样后加 UnsharpMask（radius 1.1 / 105% / threshold 3）。
- 放大幅度从 2.5× 降到 2.07×。

同时去掉了 v3 的"逐帧高度归一"——那会把蹲、俯冲这类**本来就该更矮的姿势**强行拉高，
现在保留姿势的自然高度差（全段高度差 5%，全部来自动作本身）。

---

## 3. 残留问题

1. **出拳和旋身是 GPT 分开画的两段**，风格略有差异（块 8 的头发更圆、块 9 更锐），
   接缝处能看出一点笔触变化。要彻底统一需要重画。
2. **旋身幅度偏小**：素材里更像是"手臂横扫 + 转体"，不是完整的一圈旋转。
3. **收势是合成的**：最后 3 帧是运动补偿出来的，头发和橙色轨迹会有轻微拖影。
4. 循环切点仍是"待机 → 待机"（首尾同为待机姿势，重合度 1.000），这一点是干净的。

### 重新生成

```powershell
python build_melee_v4.py      # 生成 GIF 与逐帧 PNG
python diag_seq.py seq_melee_v4   # 回读诊断：对齐抖动、单步重合度
```

调整参数（都在 `build_melee_v4.py` 顶部）：
`TARGET_H` 角色高度、`BASELINE` 地平线、`CW/CH` 画布、
出拳/旋身帧的挑选列表、`bridge()` 的相位与切换点。
